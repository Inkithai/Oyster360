# Database Migrations Policy and Lifecycle

This document describes the schema management policy, migration conventions, and regeneration procedures for Oyster360.

## Overview

Oyster360 uses [Alembic](https://alembic.sqlalchemy.org/) for database schema versioning against PostgreSQL (production) and SQLite (in-memory unit test lane). All migration scripts are located under `backend/alembic/versions/`.

## Migration Sequence

1. `001_initial_migration.py`: Initial core tables (users, farms, rooms, strains, batches, recipes, growth logs, harvests, environment logs, sensors, grow bags, ai insights).
2. `002_add_email_verification.py`: Email verification fields on the `users` table.
3. `003_add_tenant_and_operations_tables.py`: Multi-tenant organization tables, subscriptions, audit logging, feature flags, notifications, documents, chunk embeddings, suppliers, inventory items, transactions, and purchase orders.
4. `004_add_ai_and_grading_tables.py`: AI conversations, vision inspections, inspection findings, yield predictions, harvest grading, and multi-tenant foreign key relationships on existing models.

## Cleanliness & Size Policies

- **File Length Limit**: Every migration file must stay under 500 lines of code. Large multi-table additions should be split into cohesive, sequentially chained revisions.
- **Machine-Enforced Lint Exclusions**: Generated migration scripts are machine-excluded in `.flake8`, `backend/.flake8`, `setup.cfg`, `backend/setup.cfg`, and `.pre-commit-config.yaml`.
- **Idempotency & Safe Enum Upgrades**: Postgres enum types (such as `userrole` or `itemcategory`) must be updated with `ALTER TYPE ... ADD VALUE IF NOT EXISTS` checks.

## Generating New Migrations

1. Modify or add SQLAlchemy models in `backend/app/models/`.
2. Generate an autogenerated revision:
   ```bash
   cd backend
   alembic revision --autogenerate -m "describe schema change"
   ```
3. Review the generated revision:
   - Ensure foreign key constraints have explicit names.
   - Verify downgrade functions correctly reverse all table creations, column additions, and index changes.
   - If the generated file exceeds 400 lines, split the revision into two chained revisions.
4. Test running migrations forwards and backwards:
   ```bash
   cd backend
   alembic upgrade head
   alembic downgrade -1
   alembic upgrade head
   ```

## Running Migrations in Environments

- **Local Development**: `make migrate` or `docker compose exec backend alembic upgrade head`
- **CI Pipeline**: Automated via Docker integration test stack and in-memory test fixtures.
- **Production Deployment**: Automated pre-start command before starting the Uvicorn application server.
